# DSpine final runtime review — November 11, 2026

This report preserves the completed frozen-source review. The release assets and their SHA-256 hashes are listed in [assets.json](assets.json).

The results below concern **frozen source A, before engine 1.6.1**: the reviewed runtime preserved as `fa62be81f2e9c48959f10a96ae3866a30c824075`, built as `src-1c82f6775b84007778a42bac408d53e5b095ac731ed27f479e126f7203fe0283`. Integration with upstream `767c646ed91eb45a1e13a59525da7373123ac4cf` (engine 1.6.1) is a separate source. That integration changes activation policy, memory accounting and startup warmup; it needs its own validation and measurements. These rates and gates do not transfer to the integrated PR.

This follow-up restores the measured target QKV reduction at sixteen rows and adds an M48 gate/up kernel for three sixteen-row lanes. It improves a specific cloned-lane workload and the reused historical aggregate, while fresh agent and HTTP results retain substantial limits. **DFlash2 and eight-row defaults remain unchanged.** There is no universally fastest mode in these measurements.

Source A's selected [seven-file patch](patches/combined-v2.patch) is based on `37bdd4f8710319bfad43709de2725df89ef776d3`, SHA-256 `f27dc90a8d0104b7350f03c58a3ad72ff35c3aa7f5c09f29657cf14680e7e60d`. A main-checkout rebuild made before the engine 1.6.1 integration succeeded, with its native executable and two Metal libraries matching the selected serving bundle byte-for-byte. That witness describes the recorded pre-integration checkout. [Build validation](results/main-native-build-v1.validation.json), [artifact witness](results/main-runtime-bundle-witness-v1.json)

Every comparison retains its three ABBA groups, complete cohort and independent output, operating, noise and effect gates. The new historical primary includes **all 31 cases, including `count_secondary`**; the earlier report's 30-case primary excluded it. These are reused confirmation prompts, not a new holdout, and the old rates/verdicts remain unchanged.

Frozen request tokens and caps are retained for [agent12](cohorts/agent12-v1.txt), [historical31](cohorts/historical31-v1.txt) and [mixed HTTP](cohorts/mixed-serving-v1.json).

The fresh agent cohort demonstrates why context length alone cannot select a mode: at nearly the same 4K prompt length, `medium_cancel` is 6.36–6.63% slower with DSpine16 while `medium_router` is 21.32–23.18% faster, with all three per-case effect gates passing. Descriptive cycle accounting links these outcomes to emitted tokens per cycle versus GPU cost per cycle; it does not isolate a responsible operator. [Agent accounting](results/agent12-mechanisms-v1.json), [historical accounting and retained regressions](results/historical31-mechanisms-v1.json)

The HTTP workload charges four staggered requests, heterogeneous prompt lengths, prefill and later cached-prefix reuse through the normal server. Its output comparison covers full assistant text, completion counts and finish reasons; the API does not expose native token arrays. Cold/warm text changes are deterministic within the measured arms, but their causes remain unisolated. Surviving qualified own-case endpoints in the audit do not establish a clean substitution for the whole concurrent workload.

The runtime corrections are deliberately narrow. On the measured 20-core Apple M5 Pro, the unrotated AF4G64 `14336×5120` target QKV projection restores two K partitions for one sixteen-row lane. It reproduces all 31 retained eight-row arrays and all 18 captured full-vocabulary target-logit rows on the selected earliest-divergence prompt. M48 computes 48 useful gate/up rows while retaining 64-row storage and split-partial strides, for exact `17408×5120` BF16 plane tensors at B3. Other layouts/devices retain their existing selection. [QKV arrays](results/qkv-historical31-v1.analysis.json), [logit probe](results/width-base8-vs-qkv16-v1.analysis.json), [source witness](results/review-source-witness-v1.json)

Validation covers frozen source A's full CPU recipe and targeted GPU/linear/projection checks, including independent numerical bounds, M64 bit equality, padding, counters and invalid-layout rejection. The standard shader-validated all-format projection suite passes. Extra API-plus-shader validation aborts in unchanged IQ4_XS prefill; paired baseline/candidate probes reproduce the same instrumented-memory accounting interaction, with both failures preserved. [CPU log](results/build-combined-v2.stdout), [final regression protocol](notes/combined-final-regression-v1.protocol.json), [standard shader receipt](results/combined-final-default-shader-v1.receipt.json), [paired classification](results/prefill-iq4xs-validation-v1.analysis.json)

The older full sanitizer, Python, Swift, priority and cache integration results belong to their original source. They are not relabeled as validation of this patch. Measurements are finite fixtures on one M5 Pro: all agent and HTTP outputs reach their caps, and historical cases have variable caps and below-cap completions. Width remains fixed per loaded model because pending recurrent-state tape, allocation and cache identities depend on geometry. These results do not support automatic context-length selection or switching width inside an active request.

The separately [recovered historical sampling screen](results/sampling-recovery-v1.comparison.json) completes its original 280-test family with zero rejections. It does not test this selected candidate, establish distribution equality or replace the original incomplete cutoff report.

The separate source A candidate screen uses four short contexts, 1,000 new seeds per context, a 24-token cap, temperature 1, top-p 0.95 and top-k 20. All adjusted p-values are 1.0. Its recovered control observations were also used in the earlier historical screen, so the two screens are not independent replications. Non-rejection on these finite fixtures does not establish distribution equivalence, long-context behavior or end-to-end task quality. It provides no sampling evidence for the engine 1.6.1 integration.
