# Splash 1.6.2

Splash 1.6.2 keeps text a client sends from ever reading as a control token, keeps decoding requests moving when a lane at the memory limit moves its KV to the SSD, lets the SSD cache hold what its quota counts, starts constrained JSON at its first token, starts a model that streams its experts with one load of its weights, serves on a UNIX socket, lets a server set every request's reasoning effort and replace the model's chat template, takes Splash's sampling fields on the Messages API, tells a supervisor when its engine is relaunching, reports what the SSD cache writes, and keeps a new chat in the Mac app only once the server has taken its first message.

## Fixes

- **Text a request sends is never a control token** (#530). A tag that a message only quotes, such as a tool result showing `tool_call_start = "<tool_call>"`, or a `<|im_end|>` inside a document, reached the model as the token itself: replies came back empty or without the tag, and a tool result could forge a turn. Every token the tokenizer adds now reads as its characters wherever a message, a tool result or a tool definition spells it; only what the chat template writes is a token. On Qwen3.8-27B a question about a parser's tool-call tag was answered right in 50 of 50 runs (45 before), and a tool result that forged a system turn was obeyed in none of 20 (8 before). A conversation that quotes a tag keeps its tokenizer prefix. See [Upgrade](#upgrade).
- **Constrained JSON starts at its first token** (#730). With a `json_schema` response format and no reasoning, the model could spend up to 64 characters of whitespace before the value: on Qwen3.8-27B a 16-token answer was all whitespace and ended with `length`. Whitespace before the value now belongs to the reasoning that precedes it: the same request answers in 10 tokens.
- **A lane that moves its KV to the SSD at the memory limit keeps decoding.** A decoding lane that converted to Spill right after a prefill pass was refused that command and waited a second pass: in the scheduler's simulation of a Studio at 18 GB, 12 of 85 workloads around the churn's broke the decode-gap bound (about 1.07 s against 0.84 s). A conversion now releases at once the pages whose copies have landed, and a lane whose copies are still on their way holds the next prefill unit back for at most the time of one unit, so its gap never grows past what it would have waited anyway: all 85 pass, with the same requests and tokens served, and on an SSD a tenth as fast no gap is longer than before.
- **A Foreground request that takes a Background lane starts at once**, where it waited one more decode command of the lanes left: on Qwen3.8-27B its time to first token beside four Background requests fell from 194 to 124 ms.
- **The SSD cache holds what its quota counts** (#758). A copy took a whole slot of the quota, and of the volume, whatever it stored. A slot now keeps and counts only the host pages its write stores, so Flint's pages, a third of a slot each, fit about three times as many: with `--max-cache-disk 3G`, 24K-token prompts kept 8 restore points where they kept 2. A cache written by 1.6.1 is taken back as it is and returns the blocks it no longer counts at the first start. On a volume that returns no blocks of a file (not APFS), every copy counts a whole slot, as before.
- **The serve record follows an engine relaunch.** From an engine's failure until the engine started in its place serves, `serve-PORT.json` says `recovering`, then `ready` again, with the same pid, so what supervises a server can tell that load from one whose memory grows while it should be serving.
- **Split projections read their partial sums in an order the language guarantees.** Every thread that stores or reads a split's partials fences them at device scope. No output changes and no time is lost; one release check had failed under shader validation on a 20-core M5 Pro.
- **The Neural Engine split keeps the share that serves best** (#332, in part). Its calibration took the Neural Engine's slowdown of the GPU's part at the share it tried as none, which on an M5 Max left two shares 0.4% apart, so the Mac's load at the moment chose between them: Qwen3.8-27B MLX 4-bit was remembered at 6 units on a quiet Mac and 7 under load, and 7 prefills chunks above about 900 rows 1.4–1.5% faster. Calibration now measures that slowdown at its first choice and chooses again, taking the new share only where its split is prepared, serves every chunk the first did and none of them more than 2% slower: the 27B now takes 7 units on a quiet Mac, the GGUF 27B keeps 9. A first start that changes the share calibrates about 3 s longer. A calibration taken under heavy load is still remembered for the build.
- **A model whose experts stream loads its weights once at a start**, where it loaded them twice to size its stores: Qwen3.8-Flash-Next is ready 1.4 s sooner, Qwen3.6-35B-A3B at `--max-memory 18G` 0.9 s. A start whose SSD cache cannot open still loads them twice (three times in 1.6.1).
- **An agent command that finds no ready server says why**: when another server holds the port, the refusal names its pid, model, where it listens (a UNIX socket, another host) and its phase, where it said only that no server was ready.
- A custom chat template with no generation prompt is refused at startup, naming the line, rather than answering every request with a 400.

## Server

- **`--host unix:PATH`** serves HTTP on a UNIX socket instead of a TCP port (#743), for a server whose sandbox allows no IP networking. The server holds `PATH.lock` while the path is its own, replaces only a socket that refuses a connection, and removes its socket as it exits. `--port` still names its lock and serve record.
- **`--reasoning-effort EFFORT`** sets the effort of every request on Chat, Responses and Messages, whatever the request asks; `none` turns thinking off for clients that ask for it on every turn. It is refused with `--default-reasoning-effort` and on a model whose reasoning cannot be switched.
- **`--chat-template-file FILE`** replaces the model's chat template (#549). The template must write the family's tool-call layout for tool calls to be read.
- **The Messages API takes Splash's sampling fields**: `presence_penalty`, `frequency_penalty`, `repetition_penalty`, `min_p`, `ignore_eos` and `logit_bias`, with the validation and 400s Chat gives them, where it dropped them without a word. Every route now takes the same list. See [Upgrade](#upgrade).
- **`/status` and `/metrics` report the SSD cache's write rate** (#720): `disk.written_last_hour_bytes` and `disk.written_last_day_bytes`, counted as `--max-cache-disk-writes` counts them, with a budget or without.

## Mac app

- **A new chat is kept only once the server takes its first message.** A message the server refuses, or cannot be reached for, leaves the window as it was, with its text and attachments in the composer and the reason over them, where the chat was listed and opened and then taken back. The same holds for a later message that fails before the server takes it.
- **A new chat's text stays where it is** as a refusal's reason or attachments come and go over it: what is over the text grows the composer upward, where it pushed the text down 17 to 65 points.
- As a chat opens, the composer is as tall as what it holds while it moves, where it travelled as a tall empty card; what it held over its text goes at once, and the chat's title and the reason line appear in place once the composer has moved.

## Internals

- The draft's attention writes its rows where the projection reads them, and the pass that reordered them is gone; outputs are bit-identical and decode times unchanged.
- The serving benchmark gains `agent` (append-only tool loops) and `edit` (regenerated and edited earlier turns), which record bytes written, reuse and time to first token per turn.

## Upgrade

```bash
brew upgrade splash
```

Keep the CLI and desktop app on the same release.

- **Message text that spells a template's tags is text.** A client that sent a tool result as a user message spelled `<tool_response>…</tool_response>`, or reasoning as an inline `<think>…</think>` in assistant content, now sends characters: use the `tool` role and `reasoning_content`. `/v1/completions` and `/tokenize` encode their input as before.
- **A tokenizer whose added tokens cannot be kept apart from text** is refused at startup; the families Splash serves are not affected.
- **`/status`** keeps its schema and gains `disk.written_last_hour_bytes`, `written_last_day_bytes`, `kv_bytes`, `kv_blocks` and `file_bytes`, and `reasoning_effort`. `/v1/models` reports `thinks: null` under `--reasoning-effort`.
- **The serve record** has a phase `recovering`. A tool that reads it should treat a phase it does not know as "not ready".
- **Messages requests with an invalid sampling field are refused** with a 400, as on Chat, where 1.6.1 ignored the field: for example `presence_penalty` 3.
- **The app:** a first message sent to a sleeping or busy model stays in the composer until the server takes it, about 2 s at most.
