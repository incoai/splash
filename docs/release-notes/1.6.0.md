# Splash 1.6.0

Splash 1.6.0 serves within a memory limit without long stalls: one memory ledger decides what every allocation may take, idle KV no longer slows each GPU command, and the expert store grows and shrinks with free memory. It also loads more GGUF layouts, restarts a failed engine while a restart can succeed, renders PDFs in a sandbox, and adds a drawer of terminals and logs to the Mac app.

## Memory

- **One memory ledger.** Every allocation is a claim on one ledger. A claim the memory limit refuses frees memory in one fixed order, from what frees at once and caches the model rebuilds to what another request uses and, last, for a running request's KV, the state buffers the next request starts from; a request waiting for memory holds what it lacks against lower-ranked ones. `/status` reports the ledger under `memory_governor`.

  On an M5 Max with 36 GB serving Qwen3.8-Flash-Next Q2_0 at `--max-memory 18G`, each 15-minute run of a mixed load on 1.5.0 had a streaming client wait 300–406 s between two chunks. On a 1.6.0 release candidate the longest wait was 0.92 s, with 1.27x the prefill and 1.25x the decode throughput.

- **Idle KV no longer slows every command** (#644). 1.5.0 kept every KV extent in a residency set of the GPU command queue, which Metal makes resident before each command buffer, so cached KV that no request used cost every command: with 6 to 12 GiB of KV near the GPU's working-set limit, a streamed Flash-Next decode cycle took 10% to 5.8x longer (M5 Max with 36 GB, macOS 27). A command now makes resident only the KV its page tables reach. That removes the per-command cost, the likely cause of the decode slowdown reported in #644; the slowdown itself was not reproduced, so this change is not shown to end it.
- **Elastic expert store.** With `--expert-memory auto`, the default, streamed experts start at the store's floor, grow in chunks of about 1 GiB as memory allows, and give chunks back down to the floor while requests or other apps need the memory. 1.5.0 sized the store once at startup. `--expert-memory SIZE` still fixes the store at SIZE, as in 1.5.0. (#640, #645)
- **Context no longer shrinks as the budget grows.** A target whose KV cannot spill to the SSD, such as Qwen3.6-35B-A3B, loaded its experts whole wherever they fit, however little context that left, so a larger memory budget could serve less context. Experts now load whole only where they leave the first 64K tokens of context, or `--max-context`.

## Models

- **Split GGUFs at a repository root** (`MODEL-00001-of-0000N.gguf` and its parts) install as one target, with or without `:VARIANT`; 1.5.0 refused them. A whole file beside the parts of its name, such as their merge, is a target of its own, chosen first.
- **BF16 and F16 PLE tables:** Qwen3.8-Flash-Next GGUFs with such a table load and stream; 1.5.0 refused them (`unexpected size for per_layer_token_embd.weight`).
- **More Flint GGUFs:** those of lmstudio-community, ggml-org, bartowski, mradermacher and prithivMLmods, whose headers do not list the stop tokens, install; Splash takes them from the vocabulary.
- The app and shell completion suggest Flash-Next IQ3_S on Macs with 96 GB or more. (#643)
- Quantized projections outside the MoE experts run prefill chunks of 33 to 64 rows, such as a resumed turn's, on a 64-row tile instead of the 128-row one on M5 and M6 GPUs (#621), and on M3 and M4 GPUs with 10 cores or fewer.

## Serving and APIs

- **Chat token counting:** `POST /v1/chat/completions/count_tokens` counts a Chat request's prompt tokens, images included, without inference. (#642)
- **Engine restarts:** a failed engine restarts at once; one that fails again within 60 s of starting waits 5 s, doubling with each such failure in a row up to 60 s. Restarts stop at once on a failure a restart would meet again, such as a setting the engine refuses or model files it cannot serve (missing, moved or corrupt), and otherwise at the sixth failure in a row within 60 s of starting, where 1.5.0 stopped at the third. A start that failed for want of memory is retried, at most 60 s apart, for as long as it fails, and does not count toward the six. `engine_recovering` carries a `Retry-After` of the time the restart should take (1.5.0: 1 s). A restarted engine serves the first one's context, or what its memory plan holds now (`capabilities.max_context_tokens` in `/status`), where 1.5.0 stopped restarting. A relaunch starts once the old engine has exited. (#616)
- **Quarantine:** a request the engine was running at two failures in a row that a request may cause is refused with 400 `request_quarantined` until the server restarts.
- **Stop sequences** are matched as the output arrives; 1.5.0 rescanned the held text on every token, 13 s over 10,000 tokens with two 10,000-character stops.
- **PDFs** render in a process with no environment variables, sandboxed to read only the system's libraries and fonts and Splash's runtime, to write nothing, reach no network and start no program. 1.5.0's worker inherited the server's environment.
- A tool call that names no function is returned as text instead of being dropped. (#632)
- **TTFT breakdown:** the server log has one line per request at its first token, splitting its time into its own prefill, waiting for memory, decode, other requests' prefill and the rest, which `/status` reports under `metrics.ttft_parts_ms`; long decode gaps are counted by cause under `metrics.decode_gap_causes`. A resource failure's console line names the engine's reason. (#620)
- Each API's handlers live in a module of their own behind one route table, and Flint runs on the Qwen target's code with unchanged plans.

## Splash for Mac

- **Drawer:** ⌘J, or the toolbar's terminal button, opens terminals (your login shell, in tabs) and the server's and downloads' logs as they are written; a failure's Show Log opens its log there.
- The Server's button sits at the toolbar's end, and ⌘B hides the Chat's sidebar.
- Replies stream smoothly, drawing only what changed; a conversation opens on its latest messages first.
- The composer shows the prompt's share of the context as a ring beside Send, and blocks only a prompt that cannot fit. (#642, closes #641)
- Text an input method is still composing stays in the composer. (#631)
- The server the app started stops when the app crashes, not only when it quits.
- A start that fails says why, from the server's serve record, instead of "native protocol reached EOF".
- A download is refused before it starts where its volume has no room for it, in the app and the terminal alike, also where `HF_HOME` or `HF_HUB_CACHE` puts the Hugging Face cache on another volume. The SSD cache yields its own room: it shrinks, or turns off, where the disk runs short.
- A gated model the account may not read says to sign in with an account that can, or to accept the model's terms on its page, instead of that the model does not exist.
- Launch options show only what the model picked can use, such as no expert cache for Qwen3.8-27B and no vision, recurrent state or thinking options for Flint, and a start passes no other; a value set stays for a model that can use it. Context length's hint gives the model's own limit.
- Launch options take names close to their flags, such as Queue limit (was Requests at once) and Decode share (was Answering while reading), and the value that keeps every expert or the whole PLE table in memory reads All rather than Off. An info button beside an option's name, shown on hover or keyboard focus, explains it.

## Fixes

- A request alone on a model whose KV spills to the SSD cache, such as a 120K-token Flash-Next turn, no longer fails with `capacity_exhausted` while copies of its KV to the SSD cache are about to free the memory it lacks; it waits for them. (#622, fixes #613)
- `splash pi` sends the server's API key with every Pi version; Pi 0.73.1 sent the text `$SPLASH_API_KEY` and got 401.
- A served connection with input still unread, such as a pipelined request, no longer resets the answer.
- The launcher's check for a running server, and the agents `splash claude`, `splash codex`, `splash hermes`, `splash opencode` and `splash pi` start, reach the local server without a proxy: with `http_proxy` set, 1.5.0's launcher sent the server's API key to the proxy. Where the environment names a proxy, the agents get the loopback hosts added to `NO_PROXY`; a proxy set only in macOS settings keeps its own exceptions.
- A Finder `.DS_Store` in the models folder no longer makes every start of a local model fail, and a cleanup error after an update no longer reports the update as failed.
- An installation reassembled under another Hugging Face cache (one set in the shell but not the app, or the reverse) takes its files from its own snapshots, so it no longer warns on every start and takes draft updates.
- An engine whose server ends while the model loads stops, instead of loading and warming up for nothing.
- After an update, a server or download that an earlier app left running when it crashed is stopped, as 1.5.0 did, where the process still holds that server's port or runs that download.
- The app lists a model only while its files are on this Mac: one whose Hugging Face cache files were deleted, which 1.5.0 listed and failed to start, comes back once the cache holds it again or it is downloaded again.

## Upgrade

```bash
brew upgrade splash
```

Keep the CLI and desktop app on the same release.

- **Persistent cache:** its format is unchanged, so a cache carries over between 1.5.0 and 1.6.0 in both directions where the model's installation is unchanged. A GGUF installation is assembled again on its first 1.6.0 start, as the GGUF metadata adapter changed, without downloading its weights; its persistent cache then starts fresh once, and again after switching back.
- **`/status` schema 8** (was 6): `kv_spill.history_stream.contended_commands` and `memory_plan.budget.resident_kv_bytes` are gone, and a request a stop sequence ended counts under `requests.completed`, no longer `cancelled`.
- **Thinking budget:** where the context leaves a request less room than its output limit, the budget keeps its share of that room, and the answer the rest: a budget of 24,576 under a limit of 32,768 with 20,000 tokens of context left ends thinking at 15,000. 1.5.0 kept the whole budget, so thinking could take all the room the context left.
- **`--thinking-end-text`:** unset, a thinking budget's cut closes as the chat template closes a reasoning (a line break, then `</think>`, on Qwen's templates), so the next turn reuses the reply's cached KV past the cut. 1.5.0 wrote `</think>` alone.
- **Engine failures:** while restarts go on, requests get 503 `engine_recovering`; once they stop (above), 500 `engine_failed` with the reason, as `/status` reports under `transport`. A quarantined request gets 400 `request_quarantined`.
- **PDF input needs `/usr/bin/sandbox-exec`:** where it cannot apply its profile, as inside another sandbox, PDF requests get 503 `document_unavailable`.
- **GGUF selection:** `:VARIANT` takes a folder named `VARIANT` before the only root file whose name ends in `-VARIANT`. For `:Q4_K_M`, a repository with `M-UD-Q4_K_M.gguf` at its root and split parts in `Q4_K_M/` now installs the folder, where 1.5.0 took the root file.
- **GGUF screening:** a GGUF holding tensors the model would not apply, such as a converter's attention bias, is refused from its header; 1.5.0 ignored them. An NVFP4 weight's `.input_scale` is still accepted.
- **Stop sequences** longer than 16,384 characters get 400. Messages' `stop_sequences` must be an array of strings, each holding a character other than whitespace, as Anthropic's API requires; a single string, which 1.5.0 took, gets 400. Errors name `stop_sequences`.
- **Split GGUFs** are the parts of one name: a folder that mixes the parts of different names is refused, by the installer and the engine alike.
- **Engine exit statuses:** the engine exits 65 (`EX_DATAERR`) for a model directory it cannot serve, where 1.5.0 exited 64 for a missing one, and 0 when the server closes its pipe, which 1.5.0 reported as an engine failure.
